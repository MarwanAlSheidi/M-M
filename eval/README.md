# UAE Abaya Classification — Benchmark

منظومة تقييم لقياس دقّة نموذج لغوي في تحويل بيانات المنتج الخام (اسم + وصف)
إلى تصنيفات موحّدة وفق Taxonomy ثابتة للعباية الإماراتية.

| | |
|---|---|
| Benchmark | `v2.0.4` |
| Prompt | `v0.1` |
| Dataset | `v1.2` |
| Model | `gpt-4o-mini` · `temperature = 0.0` |

هذا المجلد مستقلّ تماماً عن تطبيق «الخطة المالية» في جذر المستودع؛ لا يشترك معه
في كود ولا في اعتماديات.

> **البنية:** حزمة `benchmark/` وما حولها مجذّرة هنا داخل `eval/` لا في جذر
> المستودع، لأن `scripts/` في الجذر يخصّ فحوصات تطبيق React. الترتيب النسبي
> (`benchmark/`, `configs/`, `data/`, `prompts/`, `manifests/`, `scripts/`,
> `tests/`) كما هو.

## 1. التشغيل

```bash
pip install -r eval/requirements.txt
cd eval

python -m benchmark.run_benchmark      # تشغيلة كاملة
python -m pytest                       # 181 اختباراً
python scripts/build_manifest.py --check   # هل البصمات محدّثة؟
```

المصنّف الافتراضي `mock` — حتمي، بلا شبكة، بلا مفتاح API. للتشغيل الحقيقي غيّر
`classifier: openai` في `configs/model_config.yaml` واضبط `OPENAI_API_KEY`.

المخرجات تُكتب في `runs/run_<timestamp>/`.

## 3. Canonicalizer — المرجع الوحيد للصواب

**لا تقارن قيمتين في أي مكان آخر.** كل قرار صواب يمرّ عبر
`canonicalizer.is_correct(gold, prediction, field)`. لحظة وجود تطبيق ثانٍ
لسؤال «هل القيمتان متطابقتان؟» يفترق الاثنان ويصير الرقم غير قابل للتكرار.

خريطتان منفصلتان — `ai_synonyms` و `gold_synonyms` — لأن Gold يحمل ما كتبه
المُصنِّف البشري والتنبّؤ يحمل ما أخرجه النموذج، وخريطة مشتركة تُسرّب إحدى
اللغتين إلى الأخرى. وكلتاهما **مفهرسة بالحقل**: `stone` لون في
`color_normalized` وزخرفة في `embellishment_type`.

`None == None` صواب. `None` أمام أي قيمة خطأ في الاتّجاهين.

## 4. الطبقات الأربع

| الطبقة | المحتوى |
|---|---|
| `raw` | ما أخرجه المصنّف حرفياً — لا يُعدَّل أبداً |
| `validated` | بعد فحص النوع والـ Taxonomy والدليل |
| `canonical` | الصيغة المعيارية للقيمة |
| `final` | ما يُقيَّم فعلاً (الامتناع ← `null`) |

المقاييس تُحسب على الطبقات الأربع. تطابُقها هو الحالة الطبيعية؛ **الفجوة بينها
هي النتيجة**: هبوط كبير من `raw` إلى `final` يعني نموذجاً يجيب خارج الـ Taxonomy
أو بلا دليل، وهو ما لا يُظهره أي رقم دقّة مفرد.

## 5. القرارات والدليل

`validate_field()` يعيد دائماً العقد الكامل بتسعة مفاتيح، ويقرّر:

| القرار | متى |
|---|---|
| `PREDICT` | قيمة صالحة، وسياسة الحقل تسمح بها عند درجة الدليل هذه |
| `ABSTAIN` | فراغ · نوع غير مدعوم · قيمة خارج الـ Taxonomy · دليل غائب في حقل صارم |
| `UNKNOWN` | حقل خارج الـ Taxonomy أصلاً — لا يمكن قول شيء عنه |

سياسة الدليل لكل حقل في `configs/critical_fields.yaml`:

| درجة الدليل | حقل صارم | حقل يسمح بالاستنتاج |
|---|---|---|
| `SUPPORTED` | تُحفظ الثقة | تُحفظ الثقة |
| `PARTIAL` | سقف 0.7 | سقف 0.7 |
| `UNSUPPORTED` | سقف 0.3 | سقف 0.3 |
| `ABSENT` | **ABSTAIN** | PREDICT بسقف 0.6 |

**الحقل غير المدرَج في أي قائمة يُعامل معاملة الصارم.** الافتراض الآمن مقصود:
إضافة حقل جديد إلى الـ Taxonomy يجب ألّا تمنحه ضمناً إذناً بالتخمين.

## 6. بوّابة النزاهة

13 فحصاً قبل أي تصنيف. **أي `FAIL` واحد يوقف التشغيل** عبر `IntegrityError`.

| الفحص | FAIL عند |
|---|---|
| `manifest` | غياب الـ manifest |
| `gold_file` | اختلاف بصمة Gold عن الـ manifest |
| `dataset_schema` | نقص عمود مطلوب |
| `gold_schema` | نقص عمود Taxonomy |
| `dataset_gold_alignment` | اختلاف المعرّفات · تكرارها · فراغها |
| `leakage` | تقاطع التدريب مع Gold أو Dataset |
| `taxonomy` / `synonyms` / `critical_fields` | اختلاف البصمة |
| `prompt` | اختلاف بصمة الـ Prompt المرسوم |
| `code_hashes` | اختلاف بصمة وحدة · غياب وحدة أساسية |
| `model_config` | اختلاف بصمة الإعدادات |
| `evidence_verification` | السياسة تطلبه ولا يُستورد |

`WARN` لا يوقف: بصمة غير مثبّتة في الـ manifest، أو ملف تدريب غير مُعرَّف —
وهي حالات «غير معروف»، ولا تُقرأ أبداً على أنها «نظيف».

**البصمة تُبنى يدوياً** بـ `scripts/build_manifest.py`. بناؤها تلقائياً مع كل
تشغيلة يجعل البوّابة تتحقّق من أن الملفات تطابق نفسها — أي لا تحقّق إطلاقاً.

## 7. تسرّب بيانات التدريب — طبقتان

1. **البوّابة** تقارن مجموعات المعرّفات كاملة قبل التشغيل.
2. **الـ Pipeline** يعيد الفحص لكل سجلّ أثناء التنفيذ، ويقارن كذلك بصمة النص
   لالتقاط السجلّ نفسه منشوراً تحت معرّف جديد.

الطبقة الثانية ليست تكراراً: بين البوّابة والحلقة يمكن أن يُستبدل ملف أو
يُرشَّح، وتشغيلة تفحص مرّة واحدة تقيس الملفّ الذي **كان** لديها.

كلتاهما ترفع `LeakageError`. لا تحذير ولا استمرار.

## 8. المقاييس

| المقياس | التعريف |
|---|---|
| Field accuracy | الصحيح ÷ إجمالي السجلات |
| Exact match | السجلّ صحيح فقط إذا صحّت **كل** الحقول |
| Critical exact match | السجلّ صحيح فقط إذا صحّت كل الحقول **الحرجة** |
| Abstention rate | `decision == ABSTAIN` ÷ إجمالي تنبّؤات الحقول |
| Selective accuracy | الدقّة بين ما لم يمتنع فقط |
| Evidence support rate | (SUPPORTED أو PARTIAL) ÷ التنبّؤات النهائية غير الفارغة |
| Evidence-conditioned accuracy | الصحيح بين حاملي الدليل ÷ حاملي الدليل |
| Critical field error rate | الخطأ في الحقول الحرجة ÷ إجمالي الحقول الحرجة |

يُضاف: precision / recall / F1 لكل حقل (ماكرو على كل تسمية، بما فيها
`__NULL__`)، ومصفوفة الالتباس، ونتائج كل سجلّ.

كل مقام صفري يعيد `0.0` — لا استثناء ولا `NaN`.

`__NULL__` تسمية دفترية للمصفوفات فقط، ولا تدخل أي قرار صواب.

---

## 9. التكلفة

`CostTracker` يستقبل مع كل سجلّ: الاستهلاك، ومعرّف المنتج، وصواب كل حقل، وصواب
السجلّ، و`raw_exact_match`، و`critical_exact_match`. لذلك يُخرج **التكلفة لكل
سجلّ صحيح** لا عدد الرموز وحده — وهو الرقم الذي يقرّر ما إذا كان النموذج يستحقّ
التشغيل.

يعمل بعد التقييم لا قبله: تكلفة السجلّ الصحيح لا تُعرف قبل تقييم السجلّ.

## 10. الاختبارات

```bash
cd eval && python -m pytest
```

181 اختباراً تغطّي المحاور الـ 33 المطلوبة: المحاذاة، التكرار، التسرّب، دلالة
الفراغ، المرادفات، الـ Taxonomy، الدليل، الاستنتاج، الطبقات الأربع، كل مقياس
على حدة، البصمات الست، أخطاء المصنّف، والتكلفة — بالإضافة إلى الحالات الحدّية
(`NaN`، `pd.NA`، فراغ، مسافات، أرقام، YAML/JSON تالف، معرّف اسمه `NA`).

الاختبارات تعمل على **ملفات `configs/` الحقيقية** لا على نسخة مصغّرة داخلية:
مجموعة اختبارات تخترع Taxonomy خاصّاً بها تنجح بينما الـ Taxonomy المشحون معطوب.

## 11. الإصدار السابق

`uae_abaya_classification_eval.py` هو الـ harness أحادي الملف `v1.2.0`. محفوظ
للرجوع وللمقارنة التاريخية؛ الجديد لا يستورده. الفروق الجوهرية:

- التقييم كان على قيمة واحدة، والآن على أربع طبقات.
- المرادفات كانت خريطة واحدة مسطّحة، والآن مفهرسة بالحقل وبالاتجاه.
- لم تكن هناك بوّابة نزاهة ولا فحص تسرّب ولا بصمات كود.
- الامتناع لم يكن مفهوماً قائماً بذاته، فلم تكن هناك دقّة انتقائية.
