# دليل النشر والتجربة الميدانية

> اقرأه كاملاً قبل أن تبدأ. الترتيب مقصود: خطوةٌ قبل أوانها تُنتج بياناتٍ
> يصعب تنظيفها، أو تستهلك باقتك الشهرية بلا فائدة.

## قبل أن تبدأ — ما ليس في يد الكود

هذه ليست خطوات تقنية، ولا يُغني عنها أي بناء:

| السؤال | لماذا يسبق النشر |
|---|---|
| **من يُثبت أن الإمام إمام؟** | مسار الملكية يقوم على «مراجعة يدوية» ولا إجراء محدّد لها. من يراجع؟ وبأي دليل — خطاب من الوزارة؟ شهادة من أهل الحيّ؟ اتفق على ذلك **قبل** أن يصلك أوّل طلب. |
| **من هو المشرف؟** | شخصٌ يراجع الطلبات يومياً. بلا التزامٍ منه تتراكم الطلبات وينصرف الأئمة. |
| **هل معك تصريح جمع تبرعات؟** | إن لا، فالتبرعات تبقى معطّلة — وهو وضعها الافتراضي. لا تُفعّلها بلا تصريح وزارة الأوقاف وسجلّ تجاري وحساب تاجر. |

**المرحلة الأولى تُطلق بالتطوّع العيني وحده** (`estimatedCost = 0`)، بلا أي حركة
مالية. هذا قرارٌ تنظيمي لا نقص في الكود.

## أولاً: النشر

### ١. تطبيق على Back4app

أنشئ تطبيقاً، ثم انسخ `.env.example` إلى `.env` واملأه من
*App Settings → Security & Keys*:

```
PARSE_APP_ID=...
PARSE_MASTER_KEY=...
PARSE_JS_KEY=...
PARSE_SERVER_URL=https://parseapi.back4app.com
```

`.env` لا يدخل المستودع. والـMaster Key لا يظهر في أي كود عميل أبداً.

### ٢. المخطط والفهارس

```bash
npm run schema
```

يطبّق الحقول والصلاحيات **والفهارس**. الفهارس المكانية (`2dsphere`) تُطبَّق على
MongoDB؛ إن ظهر تحذيرٌ بتخطّيها فالقرب يعمل بدونها على `geo_box`.

**ثم يدوياً من لوحة Back4app** (*Database → Indexes*): فهرس **فريد** على
`Mosques.externalId`. مخطط Parse لا يعبّر عن التفرّد، وهذا الفهرس هو الحماية
الوحيدة **قبل** وقوع التكرار — وما عداه كشفٌ بعد وقوعه.

### ٣. كود السحابة

ارفع مجلّد `cloud/` عبر Back4app CLI، أو الصق `cloud/main.bundle.js` في لوحة
Cloud Code (وهو مولَّد — لا تعدّله، بل عدّل الملفات وأعد توليده بـ
`python3 scripts/build_single_file.py`).

ثم تأكّد:

```bash
curl -X POST https://parseapi.back4app.com/functions/health \
  -H "X-Parse-Application-Id: $PARSE_APP_ID" \
  -H "X-Parse-REST-API-Key: $PARSE_REST_KEY"
```

### ٤. أوّل مشرف — لا تتخطَّ هذه

بدونها **المنصّة معطّلة**: الأئمة يطلبون ملكية مساجدهم وتبقى طلباتهم معلّقة
إلى الأبد، لأن اعتمادها يحتاج مشرفاً ولا مشرف على خادمٍ جديد.

```bash
# ١) يسجّل المسؤول حساباً من التطبيق نفسه (لتبقى كلمة المرور عنده وحده)
# ٢) ثم من جهازك:
npm run admin -- --username <اسمه>
npm run admin -- --list        # للتأكّد
```

### ٥. رفع الصور

فعّل `fileUpload.enableForAuthenticatedUser` من إعدادات الخادم. بدونه لا يستطيع
المنفّذ إرفاق صورة الإنجاز، فيعتمد الإمام على الثقة وحدها.

## ثانياً: البيانات

### تحذير الباقة المجانية

الباقة 25 ألف طلب شهرياً، **والطلبات هي القيد الملزم لا المساحة**. قِيس محلياً:
الـSDK يجمع عشرين كائناً في طلب HTTP واحد، فالاستيراد الكامل ≈911 طلباً — لكن
إن كان Back4app يحتسب كل كائنٍ داخل الدفعة طلباً مستقلاً صارت الكلفة ≈18,214،
أي ثلاثة أرباع الباقة في عملية واحدة.

**راقب العدّاد قبل الاستيراد الكامل**: استورد محافظة صغيرة، وانظر كم استهلكت.

### الاستيراد

```bash
node scripts/seed_mosques.js --governorates            # ما المتاح
node scripts/seed_mosques.js --governorate musandam    # 264 مسجداً — تجربة رخيصة
npm run seed:verify                                    # فحص التكرار بلا كتابة
node scripts/seed_mosques.js                           # الاستيراد الكامل
```

السكربت قابل لإعادة التشغيل: يعتمد `externalId` فيُحدّث ولا يُكرّر، ولا يمسّ
الحقول التشغيلية (الرصيد والملكية) عند التحديث. ويقف إن وجد تكراراً بدل أن
يكتب فوقه.

## ثالثاً: الواجهة

```bash
cd app
cp .env.example .env    # املأ VITE_PARSE_* بمفاتيح العميل — لا Master Key
npm run build
npm run verify:pwa      # يفحص التثبيت والعمل بلا إنترنت
```

انشر `app/dist` على أي استضافة ساكنة. **يجب أن تكون HTTPS**: تحديد الموقع
مرفوض بدونها، وعليه يقوم «ما حولي» وترتيب الفرص بالمسافة.

خرائط جوجل اختيارية: `VITE_GOOGLE_MAPS_API_KEY` يُفعّل الخريطة، وبدونه تعمل
الشاشة كقائمة بالمسافات. قيّد المفتاح بنطاق موقعك.

## رابعاً: التجربة الميدانية

لا تُطلق للعامّة مباشرةً. الغرض من التجربة كشف ما لا تكشفه 237 حالة اختبار:
كيف يتصرّف الناس، لا كيف يتصرّف الكود.

**النطاق المقترح:** محافظة واحدة، إمام أو اثنان تعرفهما، وخمسة متطوّعين،
وأسبوعان.

```bash
node scripts/seed_mosques.js --governorate musandam
```

**راقب هذه تحديداً — كلٌّ منها افتراضٌ لم يُختبر على بشر:**

1. **هل وجد الإمام مسجده بالبحث؟** الأسماء من بيانات الوزارة وقد تختلف عمّا
   يعرفه أهل الحيّ. إن لم يجده، فالبحث بالكلمات يحتاج مراجعة.
2. **كم استغرقت مراجعة طلب الملكية؟** وبأي دليل اقتنع المشرف؟
3. **هل علم المتطوّع بتكليفه؟** الدفع لا يصل (لا Installation مسجَّل)،
   فاعتماده على فتح التطبيق. إن لم يفتحه، فهذه أوّل أولوية بعد التجربة.
4. **هل رفع المنفّذ صورة؟** أم اكتفى بالإبلاغ؟ الصورة هي بيّنة الإمام.
5. **كم مرّة غاب مكلَّف؟** الحدّان (10 اهتمامات، 3 تكليفات) **تقديريان لا
   محسوبان** — راجعهما على أرقام حقيقية.
6. **هل اشتكى أحد من شيء لم نتوقّعه؟** هذا أهمّها.

## ما يبقى خارج التغطية — اعرفه قبل النشر

- **لم يعمل على MongoDB يوماً.** كل الاختبارات على PostgreSQL، وBack4app على
  MongoDB. وقد كشف هذا الفرق خللين فعليّين (انظر `docs/REVIEW.md`). **أوّل نشرٍ
  هو أوّل تشغيل حقيقي** — فليكن على محافظة صغيرة أولاً.
- **الإشعارات الفورية معطّلة.** يصل الخبر عبر «التنبيهات» داخل التطبيق، وهي
  قناةٌ تعمل دائماً — لكنها تتطلّب أن يفتح المستخدم التطبيق.
- **الاسترداد قيدٌ محاسبي لا تحويل**، والصرف كذلك. (لا أثر لهما في المرحلة
  الأولى لأن التبرعات معطّلة.)
- **لا عميل React Native.** واجهة الويب تُثبَّت كتطبيق وتعمل بلا إنترنت.

## قبل كل دفع ونشر

```bash
npm test                  # 176 حالة — على بديل Parse في الذاكرة
npm run lint
npm run test:integration  # 48 حالة — خادم parse-server حقيقي
npm run test:e2e          # 13 حالة — متصفّح حقيقي
```

الأخيران يتخطّيان نفسيهما بلا فشل إن غابت أدواتهما، فلا يكسران جهازاً لا
يملكها — **لكن غيابهما يعني أنك لم تختبر شيئاً**. تحقّق من أنهما عملا فعلاً.
