# دليل النشر والتجربة الميدانية

> اقرأه كاملاً قبل أن تبدأ. الترتيب مقصود: خطوةٌ قبل أوانها تُنتج بياناتٍ
> يصعب تنظيفها، أو تستهلك باقتك الشهرية بلا فائدة.

## قبل أن تبدأ — ما ليس في يد الكود

هذه ليست خطوات تقنية، ولا يُغني عنها أي بناء:

| السؤال | لماذا يسبق النشر |
|---|---|
| **من يُثبت أن الإمام إمام؟** | الطلب يحمل الآن **تأكيد موقع مقدّمه** ومسافته من المسجد، وصفته (إمام أو وكيل) — وهو أقوى ما بيدك، وليس قاطعاً. يبقى عليك أن تقرّر: أيكفي «قُدّم من عند المسجد»؟ أم تطلب خطاباً من الوزارة أو شهادةً من أهل الحيّ؟ اتفق على ذلك **قبل** أن يصلك أوّل طلب. |
| **من هو المشرف؟** | شخصٌ يراجع الطلبات يومياً. بلا التزامٍ منه تتراكم الطلبات وينصرف الأئمة. |
| **هل معك تصريح جمع تبرعات؟** | إن لا، فالتبرعات تبقى معطّلة — وهو وضعها الافتراضي. لا تُفعّلها بلا تصريح وزارة الأوقاف وسجلّ تجاري وحساب تاجر. |

**المرحلة الأولى تُطلق بالتطوّع العيني وحده** (`estimatedCost = 0`)، بلا أي حركة
مالية. هذا قرارٌ تنظيمي لا نقص في الكود.

## أولاً: النشر

### ١. تطبيق على Back4app

أنشئ تطبيقاً، ثم انسخ `.env.example` إلى `.env` واملأه من
*App Settings → Security & Keys*:

```
PARSE_APP_ID=...
PARSE_MASTER_KEY=...
PARSE_JS_KEY=...
PARSE_SERVER_URL=https://parseapi.back4app.com
```

`.env` لا يدخل المستودع. والـMaster Key لا يظهر في أي كود عميل أبداً.

### ٢. المخطط والفهارس

```bash
npm run schema
```

يطبّق الحقول والصلاحيات **والفهارس**. الفهارس المكانية (`2dsphere`) تُطبَّق على
MongoDB؛ إن ظهر تحذيرٌ بتخطّيها فالقرب يعمل بدونها على `geo_box`.

**وانظر رمز الخروج، لا آخر سطر.** الأمر يخرج بغير صفر إن لم يُطبَّق المخطط كما
هو مكتوب، ويقول أيَّ صنفٍ لم يقم وأيَّ فهرسٍ سقط. وإن قيل لك **«أصنافٌ لم تقم»**
فقف عندها ولا تمضِ إلى ما بعدها: صنفٌ غائبٌ لا صلاحيات له، ويُنشئه أوّل من يكتب
فيه بصلاحياتٍ مفتوحة. الأمر لا يحذف شيئاً، فتصحيح السبب وإعادةُ تشغيله آمنة.

**ثم يدوياً من لوحة Back4app** (*Database → Indexes*): فهرس **فريد** على
`Mosques.externalId`. مخطط Parse لا يعبّر عن التفرّد، وهذا الفهرس هو الحماية
الوحيدة **قبل** وقوع التكرار — وما عداه كشفٌ بعد وقوعه.

و`npm run preflight` يبقى **أحمر** حتى تُضيفه، فلا تُنسى هذه الخطوة صامتة.

### ٣. كود السحابة

ارفع مجلّد `cloud/` عبر Back4app CLI، أو الصق `cloud/main.bundle.js` في لوحة
Cloud Code (وهو مولَّد — لا تعدّله، بل عدّل الملفات وأعد توليده بـ
`python3 scripts/build_single_file.py`).

ثم تأكّد أن الكود حُمّل:

```bash
curl -X POST https://parseapi.back4app.com/functions/health \
  -H "X-Parse-Application-Id: $PARSE_APP_ID" \
  -H "X-Parse-REST-API-Key: $PARSE_REST_KEY"
```

**و`health` لا تُثبت إلا أن الملفّ قُرئ.** وهذا الخادم أوّلُ خادم MongoDB يعمل
عليه هذا الكود — كلُّ اختباراتنا على PostgreSQL — فشغّل الفحص الأعمق:

```bash
node scripts/preflight.js
```

يُشغّل الصيغ التي يختلف فيها المحوّلان (`containsAll` على مصفوفة، صندوق
الإحاطة، `startsWith`، `containedIn` والعدّ، الترتيب والتحميل المرافق ومساره
المنقوط) **على قاعدتك الحيّة**، ويُعيد نتيجة كلٍّ منها على حدة — فتُصلح القائمة
كاملةً في جولةٍ واحدة لا خطأً يتلوه خطأ. ويعدّ لك المساجد والمشرفين والطلبات
المنتظرة.

**ويقرأ الأقفال من قاعدتك لا من الملفّ.** كلُّ ما يمنع الكتابة من متصفّح في هذه
المنصّة صلاحياتٌ في المخطط (CLP)، وعلى **الحذف لا حارس غيرها**. فيُقابَل ما في
القاعدة بما يجب أن يكون: سبعةُ أصنافٍ لا يكتب فيها عميلٌ بحال، وحقولٌ لا تصله
ولو قرأ الصفّ (هواتف الأئمة، مراجع الدفع، أرصدة المساجد). وإن رأيت
**«أبوابٌ مفتوحة»** فالباب مسمّىً ومعه مَن فُتح له — أعِد `npm run schema`، ولا
تفتحها من اللوحة.

**ويفحص الخطوتين اليدويتين لا يثق بهما:** الفهرس الفريد يُختبر بمحاولة كتابة
معرّفٍ مكرَّر (ويُحذف ما كتبه)، والجدولة تُقاس بأثرها في `_JobStatus`. فلا
يصير التقرير أخضر بالكود وحده — **يبقى أحمر حتى تُنفَّذ الخطوة اليدوية**، وهذا
هو الغرض: ما يُنسى لا يُقرأ سليماً.

**وما لا يُفحص يُذكر ومعه سببُ امتناعه** — وأهمُّه رفع الملفات: الفحص يجري
بالمفتاح الرئيس، والرفع به ينجح ولو كان معطّلاً للمصادَقين، فيُعطي أخضرَ
كاذباً. جرِّبه من التطبيق بحساب متطوّع.

أعِد تشغيله بعد كل خطوة من الخطوات التالية — فهو يقيس تقدّمك فيها.

### ٤. أوّل مشرف — لا تتخطَّ هذه

بدونها **المنصّة معطّلة**: الأئمة يطلبون ملكية مساجدهم وتبقى طلباتهم معلّقة
إلى الأبد، لأن اعتمادها يحتاج مشرفاً ولا مشرف على خادمٍ جديد.

```bash
# ١) يسجّل المسؤول حساباً من التطبيق نفسه (لتبقى كلمة المرور عنده وحده)
# ٢) ثم من جهازك:
npm run admin -- --username <اسمه>
npm run admin -- --list        # للتأكّد
```

### ٥. جدولة المهام الدورية

من *Server Settings → Background Jobs* في لوحة Back4app:

| المهمة | التواتر | ماذا يقع إن أُهملت |
|---|---|---|
| `pruneAuditLog` | أسبوعياً | سجل التدقيق ينمو بلا حدّ حتى تمتلئ القاعدة |
| `pruneNotifications` | أسبوعياً | صندوق الوارد ينمو **أسرع** — سطرٌ لكل مستهدَف لا لكل حدث |
| `reviewPendingDonations` | كل ساعة | لا أثر لها في المرحلة الأولى (التبرعات معطّلة) — تُجدوَل يوم تُفعَّل |

**لا تتخطَّ هذه.** الباقة المجانية 250 ميغابايت، والمساجد وحدها 22 منها. بلا
تقليمٍ دوريّ تمتلئ القاعدة بعد أشهر ولا يظهر السبب إلا بالبحث.

**وصدِّر قبل أن يحذف التقليم.** `pruneAuditLog` يحذف نهائياً ما تجاوز 180
يوماً، وسجلُّ التدقيق هو دليلُ الشفافية التي قامت عليها المنصّة:

```bash
npm run export            # إلى backups/masjidi-<التاريخ>.json
```

يُصدِّر طلبات الملكية وسجلّ التدقيق والطلبات والاهتمامات والمعاملات. **ولا
يُصدّر الحسابات قصداً**: فيها هواتف الناس، وسجلُّ التدقيق مبنيٌّ على ذكر الصفة
لا الهوية. والملفّ يقول في رأسه ما ينقصه ولماذا. **وهو للمساءلة والانتقال لا
للاسترجاع الآليّ** — لا يُعيده هذا السكربت إلى القاعدة.

شغّله شهرياً على الأقل، وقبل أي ترقيةٍ أو انتقالِ ملكية. و`backups/` خارج
المستودع (`.gitignore`) — فاحفظه حيث تحفظ ما يهمّك.

### ٦. رفع الصور

فعّل `fileUpload.enableForAuthenticatedUser` من إعدادات الخادم. بدونه لا يستطيع
المنفّذ إرفاق صورة الإنجاز، فيعتمد الإمام على الثقة وحدها.

وهذه خطوةٌ يدوية، أي أنها تُنسى. فإن نُسيت **لم يُترك المنفّذ في طريقٍ مسدود**:
الخادم يردّ `130 · File upload by public is disabled.`، وتعرضها الواجهة
بالعربية مع مخرجها — «تعذّر رفع الصور… ويمكنك الإبلاغ بلا صور»
(`app/src/errors.js`). لكنّ ذلك ستْرٌ للعطب لا إصلاحٌ له: **فعّلها.**

## ثانياً: البيانات

### ما قِيس على البيانات كاملةً

شُغّلت الـ18,214 على خادم حقيقي (PostgreSQL) قبل كتابة هذا:

| العملية | الزمن |
|---|---|
| بحث بالكلمات | 69–169 مللي |
| بحث مصفّى بالمحافظة | 24 مللي |
| أسوأ حالة (جزء من داخل كلمة) | 180 مللي |
| القرب الجغرافي 1–50 كم | 4–34 مللي |
| حجم القاعدة | 22 ميغابايت (منها 6 فهارس) |

المساحة ليست قيداً: 22MB من أصل 250MB.

### 414 مسجداً بإحداثيٍّ كاذب — اعرف هذا قبل الاستيراد

بيانات الوزارة تحمل قيمةً افتراضية مكان الإحداثيّ المجهول: النقطة
`23.59768, 58.42077` عليها **154 مسجداً في 45 ولاية** — من صلالة إلى دبا إلى
نزوى. ومساجدُ في «منح» بالداخلية إحداثياتها في **دبي**. المجموع 414 مسجداً
(2.27٪): 305 بقيمةٍ افتراضية مشتركة، و109 مُزاحة عن ولايتها.

الاستيراد **يسحب الثقة** من هذه الإحداثيات تلقائياً فتصير المساجد «مجهولة
الموقع» (430 مع الستة عشر التي لا إحداثيّ لها أصلاً). وهو الصواب: موقعٌ خاطئ
يُظهر مسجد صلالة لمتطوّعٍ في مسقط ويُخفيه عن أهله، وموقعٌ مجهول يُبقي المسجد في
البحث بالاسم ويجيء آخر قائمة القرب موسوماً.

```bash
node scripts/seed_mosques.js --coord-report   # ما سُحبت ثقته ولماذا
```

**وما يعنيه هذا لك تشغيلياً:** أهل هذه المساجد لن يجدوها بالبحث حولهم حتى
يثبّت إمامها موقعها. والطريقان قائمان بلا تدخّل منك:

- مسجدٌ يُسجَّل الآن: إحداثيّ طلب الملكية يُتبنّى عند اعتمادك الطلب. **وبطاقة
  الطلب تنبّهك** إلى أن اعتمادك يمنح المسجد موقعه الدائم، ومعها بُعد الموقع
  المُرسل عن أقرب مسجدٍ معروف في الولاية. وما جاوز 80 كم يُردّ آلياً لحظة
  التقديم — رقمٌ مقيس فوق أقصى ما في البيانات (73.4 كم)، فلا يُقصي قائماً.
- مسجدٌ سُجّل من قبل: يرى إمامه في «مساجدي» تنبيهاً وزرَّ **«ثبّت موقع المسجد
  من هنا»** يضغطه وهو عنده.

### استخراج المواقع من الخرائط المفتوحة — بلا مفتاح وبلا فاتورة

انتظارُ أن يقف 430 إماماً عند مساجدهم يؤخّر أهلها إلى أجلٍ غير معلوم. ومواقع
المساجد موجودة في الخرائط، و**OpenStreetMap** مفتوحة بترخيص ODbL: تنزيلٌ واحد
مجاني يأتي بكل مساجد السلطنة، ثم تجري المطابقة على جهازك بلا شبكة.

**لا مفتاح، ولا حساب، ولا عدّاد طلبات، ولا فاتورة.** وإعادة التشغيل مجانية.

```bash
node scripts/resolve_locations.js --fetch     # التنزيل — الخطوة الوحيدة التي تحتاج شبكة
node scripts/resolve_locations.js             # المطابقة، بلا شبكة
node scripts/resolve_locations.js --report    # ماذا خرج ولماذا رُدّ
```

يُخرج ملفَّين: `data/osm-mosques.json` (ما نُزّل) و`data/resolved_locations.json`
(التراكب). **راجِع الثاني** ثم أودِعهما المستودع، فيقرأ الاستيراد التراكب بعدها
بلا شبكةٍ أصلاً.

**وما رُدّ فقد رُدّ قصداً.** نقطة الخريطة مرشَّحٌ لا حقيقة، ولا تُقبل إلا
باجتماع خمسة: بيتُ صلاةٍ باسمٍ مطابق، وموضعٌ معقولٌ في الولاية، وأقربُ مسجدٍ
معلومٍ إليه من ولايتنا لا من جارتها، وغيرُ مأخوذ بمسجدٍ نعرفه **في أي ولاية**،
ولا مرشّح آخر يزاحمه. **توقّع أن يُردّ كثير** — «مصلى العيدين» في الولاية
الواحدة سبعةٌ وثمانون، ولا يُعرف أيُّها. وما رُدّ يبقى مجهولاً حتى يثبّته إمامه.

**واقرأ سطور «كاد يطابق» في التقرير.** حين يُردّ مسجدٌ لأن لا اسم يطابقه يبقى
سؤالان: أقاعدتُنا أضيق مما ينبغي، أم أن المسجد ليس في الخريطة أصلاً؟ فتُطبع
معه أقربُ الأسماء التي كادت تطابق، والفرقُ يظهر في نظرة:

```
  نزوى — «السيدة حفصة بنت عمر» ← «مسجد حفصة بنت عمر» (3)
```

هذا السطر يقول إن القاعدة ضيّقة. **وقد عولجت حالةٌ منه بالفعل:** ألقابٌ مثل
«الصحابي» و«السيدة» و«الإمام» تتصدّر 63 من الـ430 ولا تكاد تُكتب في الخرائط،
فصارت تُطرح قبل المقارنة. إن رأيت نمطاً آخر مثله فأخبرني به — هو أنفعُ من
الرقم المجرَّد.

**والترخيص يشترط النسبة:** «© مساهمو OpenStreetMap» مكتوبةٌ في كل ملفٍّ يُخرجه
السكربت، **ومعروضةٌ في شاشة «حسابي»** في التطبيق. لا تحذفها.

**ومن وقف عند المسجد أعلمُ بموضعه من أيّ مصدر.** ما استُخرج من الخرائط تقديرٌ
لا يقين، وإحداثيّ الوزارة كذب في 414 موضعاً. فالإمام أو الوكيل **يصوّب** الموقع
المسجَّل من عند المسجد، ويُقيَّد التصويب في سجلّ المسجد ومعه ما كان قبله. وما
مصدرُه إنسانٌ **لا ينسخ الاستيرادُ فوقه ولا يمحوه أبداً** — فشغّله متى شئت.

**والملفّ يُفحص من جديد عند الاستيراد.** راجِعه وحرّره إن شئت — لكنّ ما حُرّر
يُكتب في موقع مسجدٍ على الخريطة، فالاستيراد يعيد فحص كل مدخلةٍ بالقاعدة نفسها:
إحداثيٌّ صالح، وقريبٌ من مساجد ولايته. وما رُدّ **يُطبع باسمه وسببه** — فلا
يظنّ أحدٌ أن مسجداً استعاد موقعه وهو لم يستعده.

**راقب في أوّل شهر كم مسجداً استعاد موقعه** — `locationSource` في `Mosques`
يقول المصدر: `ministry` أو `claim` أو `imam`. وإعادة الاستيراد لا تمسح ما
تعلّمه المسجد.

### تحذير الباقة المجانية

الباقة 25 ألف طلب شهرياً، **والطلبات هي القيد الملزم لا المساحة**. قِيس محلياً:
الـSDK يجمع عشرين كائناً في طلب HTTP واحد، فالاستيراد الكامل ≈911 طلباً — لكن
إن كان Back4app يحتسب كل كائنٍ داخل الدفعة طلباً مستقلاً صارت الكلفة ≈18,214،
أي ثلاثة أرباع الباقة في عملية واحدة.

**راقب العدّاد قبل الاستيراد الكامل**: استورد محافظة صغيرة، وانظر كم استهلكت.

### الاستيراد

```bash
node scripts/seed_mosques.js --governorates            # ما المتاح
node scripts/seed_mosques.js --governorate musandam    # 264 مسجداً — تجربة رخيصة
npm run seed:verify                                    # فحص التكرار بلا كتابة
node scripts/seed_mosques.js --all                     # الاستيراد الكامل — يُطلب صراحةً
```

السكربت قابل لإعادة التشغيل: يعتمد `externalId` فيُحدّث ولا يُكرّر، ولا يمسّ
الحقول التشغيلية (الرصيد والملكية) عند التحديث. ويقف إن وجد تكراراً بدل أن
يكتب فوقه.

## ثالثاً: الواجهة

```bash
cd app
cp .env.example .env    # املأ VITE_PARSE_* بمفاتيح العميل — لا Master Key
npm run build
npm run verify:pwa      # يفحص التثبيت والعمل بلا إنترنت
```

انشر `app/dist` على أي استضافة ساكنة. **يجب أن تكون HTTPS**: تحديد الموقع
مرفوض بدونها، وعليه يقوم «ما حولي» وترتيب الفرص بالمسافة.

خرائط جوجل اختيارية: `VITE_GOOGLE_MAPS_API_KEY` يُفعّل الخريطة، وبدونه تعمل
الشاشة كقائمة بالمسافات. قيّد المفتاح بنطاق موقعك.

## رابعاً: الإطلاق الشامل

**النطاق: السلطنة كاملةً** — 18,214 مسجداً في إحدى عشرة محافظة، وكل الأدوار
مفتوحة (إمام، متطوّع، شركة معتمدة، مشرف)، ومسار التطوّع العيني كاملاً من طلب
الملكية إلى اعتماد العمل بصورته.

التبرعات وحدها تبقى معطّلة، وهذا **قيد تنظيمي لا نقص في الكود**: جمع التبرعات
للمساجد يخضع لوزارة الأوقاف ويتطلّب تصريحاً، والبوابة تتطلّب سجلاً تجارياً
وحساباً تاجراً. تُفعَّل يوم يصدر التصريح، والكود جاهز لها.

### تدرّج الاستيراد — لا لتقليص النطاق بل لحماية الباقة

الوجهة كل السلطنة، لكن **الوصول إليها على مرحلتين** يحمي باقتك من أن تُستنفد
في عملية واحدة قبل أن تعرف كم تكلّف:

```bash
node scripts/seed_mosques.js --governorate musandam   # ٢٦٤ — قِس ما استهلكته
# انظر عدّاد الطلبات في لوحة Back4app، ثم:
node scripts/seed_mosques.js --all                    # الباقي — ١٨٬٢١٤
```

**والسكربت يسند هذا التدرّج لا يكتفي بذكره:** تشغيلُه بلا وسائط يُردّ ويطبع
الكلفة بالاحتسابين ويدلّ على المحافظة الواحدة. فالاستيراد الكامل يُطلب باسمه
(`--all`) — **وهو البابُ الوحيد الذي لا رجعة منه**: كلُّ ما عداه idempotent
يُعاد بلا ثمن، وإنفاقُ الباقة لا يُعاد.

السكربت idempotent، فالثاني يُحدّث ما استوردته أوّلاً ولا يُكرّره. وإن تبيّن أن
الاحتساب لكل كائنٍ لا لكل دفعة، فوزّع الاستيراد على شهرين بـ`--governorate`
أو ارفع الباقة.

### ما يُراقَب في أوّل أسبوعين

الإطلاق شامل، لكن الانتباه في أوّل أسبوعين مركَّز — كلٌّ من هذه افتراضٌ لم
يُختبر على بشر بعد:

1. **هل وجد الإمام مسجده بالبحث؟** هذه أوّل عقبة وأهمّها على مستوى السلطنة:
   **«مصلى العيدين» اسمٌ لـ369 مسجداً**، و«العيدين» لـ161.

   قِيس على البيانات كاملةً — مئتا مسجدٍ من كل المحافظات، الإمام واقفٌ عند
   مسجده يبحث باسمه:

   | | مسجده أوّلَ النتائج | غاب تماماً |
   |---|---|---|
   | بلا مشاركة الموقع | 135 / 200 | 1 |
   | بمشاركة الموقع | **200 / 200** | 0 |

   **فمشاركة الموقع ليست تحسيناً بل هي الفرق بين أن يجد مسجده وألّا يجده.**
   وشاشة البحث تطلبه، ومن رفض يرى الترتيب الطبيعي — راقب كم يرفض.
   الشاشة تُصفّي بالمحافظة وتعرض القرية وترشد إلى إضافة اسم القرية («العيدين
   المنجرد» يُرجع نتيجةً واحدة). **راقب هل يفهم الإمام ذلك من تلقائه**، وإن لم
   يفهم فالإرشاد يحتاج صياغةً أوضح أو تصفيةً بالولاية كذلك.
2. **كم استغرقت مراجعة طلب الملكية؟** وبأي دليل اقتنع المشرف؟
3. **هل علم المتطوّع بتكليفه؟** الدفع لا يصل (لا Installation مسجَّل)،
   فاعتماده على فتح التطبيق. إن لم يفتحه، فهذه أوّل أولوية بعد التجربة.
4. **هل رفع المنفّذ صورة؟** أم اكتفى بالإبلاغ؟ الصورة هي بيّنة الإمام.
5. **كم مرّة غاب مكلَّف؟** الحدّان (10 اهتمامات، 3 تكليفات) **تقديريان لا
   محسوبان** — راجعهما على أرقام حقيقية.
6. **هل اشتكى أحد من شيء لم نتوقّعه؟** هذا أهمّها.

**ولأن النطاق شامل، راقب هذين أيضاً:**

7. **عدّاد الطلبات الشهري.** 18 ألف مسجد يعني بحثاً وتصفّحاً أكثر بكثير مما
   تفترضه باقةٌ مجانية. راقبه أسبوعياً لا شهرياً.
8. **كم مسجداً استعاد موقعه؟** 430 مسجداً مجهول الموقع، وأهلها لا تصلهم فرصُ
   مساجدهم بالقرب. إن بقي العدد على حاله بعد شهر فالزرّ لا يُرى أو لا يُفهم.
9. **تراكم طلبات الملكية.** بمسجدٍ واحد لكل إمام، إحدى عشرة محافظة تعني طلبات
   من كل مكان دفعةً واحدة. مشرفٌ واحد لن يكفي — رتّب لمشرفٍ ثانٍ قبل أن تتكدّس،
   و`npm run admin -- --list` يُظهر من هم.

## ما يبقى خارج التغطية — اعرفه قبل النشر

- **لم يعمل على MongoDB يوماً.** كل الاختبارات على PostgreSQL، وBack4app على
  MongoDB. وقد كشف هذا الفرق خللين فعليّين (انظر `docs/REVIEW.md`). **أوّل نشرٍ
  هو أوّل تشغيل حقيقي** — فليكن على محافظة صغيرة أولاً.
- **الإشعارات الفورية معطّلة.** يصل الخبر عبر «التنبيهات» داخل التطبيق، وهي
  قناةٌ تعمل دائماً — لكنها تتطلّب أن يفتح المستخدم التطبيق.
- **الاسترداد قيدٌ محاسبي لا تحويل**، والصرف كذلك. (لا أثر لهما في المرحلة
  الأولى لأن التبرعات معطّلة.)
- **لا عميل React Native.** واجهة الويب تُثبَّت كتطبيق وتعمل بلا إنترنت.

## قبل كل دفع ونشر

```bash
npm run verify          # الطبقات الخمس كلُّها، ويرفض أن يُقرأ التخطّي نجاحاً
npm run verify -- --quick   # الفحص والوحدة وحدهما، أثناء التطوير
```

يُشغّل: الفحص (`lint`)، و358 حالة وحدة، و192 اختبار تكامل على `parse-server`
حقيقي فوق PostgreSQL، و31 حالة في متصفّح حقيقي، وفحص التثبيت (PWA).

**ولماذا لا تُشغَّل الأربع بأيديك:** اختبارا التكامل والمتصفّح **يتخطّيان
نفسيهما بلا فشل** إن غابت أدواتهما — تصميمٌ مقصود كي لا يُكسَر جهازُ من لا
يملك PostgreSQL أو Chromium. وثمنُه أن مخرجاتهما **تُشبه النجاح**:

```
# pass 0      # fail 0      # skipped 18      ← ورمز الخروج صفر
```

فيقرؤها القارئ نجاحاً وهي «لم يُختبر شيء». و`verify` يقرأ عدد المتخطَّى
**ويعدّه سقوطاً**. لا يُغني عنه انتباهُ إنسانٍ عند كل نشر.
