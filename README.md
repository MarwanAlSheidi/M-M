# خطتي المالية — تطبيق الخطة المالية الخماسية

تطبيق تخطيط مالي عربي (RTL) موجّه لعملاء كوتش مالي في عُمان والخليج. ثماني شاشات،
محرّك حسابي واحد، وتقرير جلسة قابل للطباعة والتصدير.

الجمهور: عميل يملأ خطته على الجوال، وكوتش يقرأ التقرير قبل الجلسة.

---

## التشغيل

```bash
npm install
npm run dev            # خادم التطوير
npm run build          # بناء للإنتاج
npm run verify         # المحرّك + الجوال + PWA (انظر أدناه)
npm run verify:mobile  # فحص الجوال وحده
npm run verify:pwa     # فحص التثبيت والعمل بلا إنترنت
npm run icons          # إعادة توليد الأيقونات
```

## التثبيت على الجوال (PWA)

التطبيق قابل للتثبيت على الشاشة الرئيسية ويعمل **بلا إنترنت** بعد أول فتح.

- **iPhone (Safari):** شارك ← «إضافة إلى الشاشة الرئيسية».
- **Android (Chrome):** تظهر لافتة التثبيت تلقائياً، أو من القائمة «تثبيت التطبيق».

يفتح بأيقونته بلا شريط متصفّح. **يتطلّب HTTPS** (أو `localhost`) — عامل الخدمة
لا يعمل على `http://` عادي.

تفاصيل تُنسى فتُكسر:

- **iOS يتجاهل أيقونات الـ`manifest` تماماً** ويقرأ `apple-touch-icon` وحدها،
  ويحتاج `apple-mobile-web-app-capable` ليفتح بلا شريط المتصفّح. الوسمان القديم
  والجديد موجودان معاً لأن Safari لم يعتمد الجديد بعد.
- **`start_url` و`scope` نسبيّان (`./`)** مثل `base`، وإلا فشل التثبيت عند الرفع
  إلى مجلّد فرعي.
- **التخزين المسبق يشمل حزمة الرسوم** رغم أنها تُحمَّل كسولاً: بقاء شاشة «القراءة»
  معطّلة بلا شبكة أسوأ من تنزيل 103ك مرة واحدة في الخلفية بعد أول فتح.
- **`verify-engine` يعطّل عامل الخدمة عمداً** (`serviceWorkers: "block"`) لأن
  تخزينه المسبق يجلب كل الأصول فيُفسد قياس التحميل الكسول. فحص PWA في سياق
  منفصل — `scripts/check-pwa.mjs`.

## هذا الملف يحدّث وثيقة التسليم الأصلية

وثيقة التسليم الأصلية كُتبت والتطبيق داخل بيئة Artifacts. **القسمان 0 و8 منها لم يعودا
دقيقين** — ما يلي هو الحالة الفعلية.

### القسم 0: افتراضات بيئة Artifacts — كلها عولجت

| الافتراض في الوثيقة | الحالة الآن |
|---|---|
| `window.storage.get/set` | استُبدل بـ `src/lib/storage.js` فوق `localStorage`، بنفس الواجهة تماماً |
| Tailwind بلا مُصرِّف | Tailwind مُصرَّف فعلياً (`tailwind.config.js` + PostCSS)، والعرض ما زال inline styles |
| `recharts` مثبّتة مسبقاً | مثبّتة في `package.json` |
| الخطوط عبر `@import` في `<style>` | انتقلت إلى `<link>` في `index.html` |

القيود الثلاثة في القسم 9 المتعلقة ببيئة Artifacts (`localStorage` محجوب،
`window.confirm` محجوب، `window.print` محجوب) **لم تعد قائمة تقنياً**، لكن
الأنماط التي فُرضت بسببها بقيت عمداً: التأكيد من خطوتين أوضح من `confirm`،
وتصدير HTML المستقل يبقى المسار الأفضل لمشاركة تقرير مع عميل.

### القسم 8: المتبقّي — أُنجز بالكامل

1. ✅ **الهوية البصرية من Stitch** — طُبّق نظام «Horizon Financial» من مشروع Stitch
   (الألوان، عائلتا الخط، أنصاف الأقطار، الظلال). الثابت `T` أعلى
   `src/khutta-maliya.jsx` هو نقطة التبديل الوحيدة.
2. ✅ **جدول الديون** — صفوف دين برصيد ونسبة فائدة وحد أدنى، ومقارنة الانهيار
   الجليدي بكرة الثلج (المدة والفائدة الإجمالية).
3. ✅ **تعديل التضخّم** — تكلفة الهدف تُدخَل بأسعار اليوم وتُضخَّم اسمياً حسب موعدها
   قبل دخولها المحاكاة.
4. ✅ **حاسبة الزكاة** — 2.5٪ على الأصول الزكوية، مع النصاب والحول.
5. ✅ **وضع الكوتش** — عملاء متعددون بفهرس منفصل وتصدير جماعي.
6. ⚠️ **قبل أي استخدام تجاري** — لم يُنجَز، وليس مهمة برمجية: بطاقات القرار
   **غير مقنَّنة** ولم تُختبر على عيّنة خليجية. التنبيه موجود في الواجهة وفي
   التقرير المصدَّر، لكن عرضها كأداة تشخيص يحتاج مراجعة مختصّ.

## البنية

```
index.html                 الخطوط + جذر RTL
src/main.jsx               نقطة الدخول
src/khutta-maliya.jsx      التطبيق كاملاً (ملف واحد بقصد)
src/CashflowChart.jsx      الرسم البياني — مفصول ليُحمَّل كسولاً
src/lib/storage.js         غلاف التخزين — البديل عن window.storage
scripts/verify-engine.mjs  اختبار انحدار المحرّك
```

الملفان المفصولان عن `khutta-maliya.jsx` مفصولان لسبب تقني لا أسلوبي:
`storage.js` ليسهل استبدال طبقة التخزين (Supabase/Firestore مثلاً) بلمس ملف
واحد، و`CashflowChart.jsx` لأن التحميل الكسول لا يعمل داخل الملف نفسه.

`khutta-maliya.jsx` ملف واحد عمداً، لكنه مقسوم داخلياً إلى ثلاث طبقات:

1. **ثوابت وبيانات** — `T` (الهوية البصرية)، `CARDS`، `TYPES`، `Q`، جداول البنود.
2. **دوال حساب صرفة** بلا React — `computeIdentity`, `computeCalc`,
   `computeDebtPlan`, `buildReport`, `buildReportHtml`. مفصولة عن المكوّن كي
   تعمل على بيانات أي عميل أثناء التصدير الجماعي، لا على الحالة المفتوحة فقط.
3. **المكوّن** — يغلّف كلاً منها في `useMemo` ولا يحسب شيئاً بنفسه.

## التخزين

| المفتاح | المحتوى |
|---|---|
| `khutta-maliya:clients-v1` | فهرس العملاء `[{id, name, updatedAt}]` |
| `khutta-maliya:active-v1` | معرّف العميل المفتوح |
| `khutta-maliya:plan:<id>` | خطة عميل واحد |
| `khutta-maliya:v2` | **قديم** — خطة واحدة، تُرحَّل تلقائياً إلى أول عميل |

**التخزين كلّه في `localStorage`** — يمسحه المتصفّح بلا إنذار (تصفّح خاص، ضغط
مساحة، «مسح بيانات التصفّح»). لذلك «تصدير نسخة» و«استيراد نسخة» زوج لا يُفصل:
تصديرٌ بلا استيراد نسخةٌ لا تُستعاد. الاستيراد يُنشئ عميلاً **جديداً** ولا
يكتب فوق الحالي، فاستيراد ملف خاطئ لا يمحو خطة قائمة. ويُشترط في الملف مفتاح
واحد على الأقل من بنية الخطة، لأن `migrate()` تملأ الفراغات بالقيم الافتراضية
فأيّ JSON عشوائي يصير خطةً فارغة تبدو سليمة.

الحفظ مؤجّل 700ms. `migrate()` تحوّل `months[60]` القديمة إلى `goals[]` وتحذف
`lik`/`ch`/`risk`. **لا تكسرها — فيها بيانات مستخدمين.**

**`migrate()` هي حدّ التطهير الوحيد** — يمرّ بها كل ما يدخل التطبيق: التحميل من
التخزين، والاستيراد من ملف، وترحيل النسخة القديمة. لذلك التحقّق من الأنواع فيها
لا في مواضع الاستخدام، وهي تعيد بناء `assets`/`liabs`/`exp`/`inc` من الجداول
المرجعية بدل الوثوق بالوارد، وتُسقط إجابات البطاقات التي فهرسها خارج مدى خيارات
البطاقة.

السبب ليس التأنّق: الانهيار في هذه الطبقة **دائم لا عابر**. الخطة تُحفَظ في
`localStorage`، فتُقرأ عند كل إقلاع وتنهار من جديد — يبقى التطبيق معطوباً بلا
مخرج إلا مسح تخزين المتصفّح يدوياً. ملفٌ واحد فيه `exp:null` أو `ans:{c1:99}`
كان يكفي. يفحص `npm run verify` سبع حمولات مشوّهة ويشترط بقاء التطبيق حيّاً
**بعد إعادة التحميل** لا عند الاستيراد فقط.

**ترتيب المصفوفات ملزم:** `assets[2]` الاستثمارات و`assets[3]` التقاعد، وهما
وحدهما ما يدخل حساب الاستقلال المالي. `exp` تُقرأ بالمفتاح لا بالفهرس
(`housing`, `debt`) لأن التسميات قابلة للتحرير.

## اختبار المحرّك

الوثيقة الأصلية تنصّ: «بعد أي تعديل على المحرّك، أدخل هذا الملف وتأكد من تطابق
المخرجات». هذا مُؤتمَت الآن:

```bash
npm run verify
```

يبني التطبيق، يشغّله في متصفّح حقيقي، يزرع حالة الاختبار من القسم 7، ويقارن ما
يُعرض فعلاً بالقيم المتوقّعة — بما فيها **الفخّ**: «المتاح فعلياً» للسنة الأولى
يجب أن يكون صفراً، لأن الفائض يُخصَّص لإغلاق فجوة الطوارئ قبل تمويل أي هدف. لو
أظهرت السنة الأولى «ضمن الفائض ✓» فقد رجع أحدهم إلى المقارنة الساذجة.

يغطي أيضاً: تعديل التضخّم، حاسبة الزكاة (فوق/دون النصاب، اكتمال الحول)، ومقارنة
الانهيار الجليدي بكرة الثلج.

### نصوص التوصيات مشروطة لا ثابتة

جُمل «الخطوات التالية» والتنبيهات تُبنى من الأرقام، فيجب أن تُفحص شروطها قبل
صياغتها. أمثلة أُصلحت لأنها كانت تُصاغ بلا شرط:

- «تأجيل أهداف الطموح (0 ر.ع.)» حين لا توجد أهداف طموح أصلاً.
- «خفض الرغبات بمقدار 0 ر.ع.» لعميل عجزُه كلّه في الاحتياجات.
- «خفض الرغبات بمقدار X» حين تكون الرغبات أقل من العجز، فتوهم أنها تُغلقه.

القاعدة: أي رقم يدخل جملة توصية يحتاج فرعاً لحالة الصفر وحالة عدم الكفاية.

ومن الصنف نفسه: `fiFor` كانت تبدأ الحلقة من `y=1` فلا تختبر الرصيد الابتدائي،
وتشترط فائضاً موجباً قبل فحص البلوغ. فمن بلغ هدفه يُقال له «سنة واحدة»، ومتقاعد
بمحفظة كافية وفائض سالب — وهي حال مرحلة «الإنفاق» التي يعرضها التطبيق — يُقال له
«لا فائض حالياً» عن استقلال بلغه فعلاً. تُعيد الدالة الآن `0` لمن بلغه، **والصفر
زائف في JS** فكل مواضع الاستخدام تختبر `!== null` لا الصدق.

كذلك: أرقام التقرير لا تُشتق من `byTier` (المقيَّد بمرشّح الأفق في شاشة الأهداف)
بل من `byTierAll`. وإلا تغيّر التقرير المطبوع بتغيّر مرشّح عرض، وخرج للعميل
الواحد تقريران مختلفان لأن التصدير الجماعي يمرّر 60 دائماً.

### فحص الجوال

`npm run verify` يشغّل بعده `scripts/check-mobile.mjs` على 390px — المقاس الذي
يُملأ به التطبيق فعلاً، وهو مقاس شاشات Stitch نفسها. يرصد أمرين في كل شاشة:

1. **التمدّد الأفقي:** جسم الصفحة لا يتمرّر أفقياً أبداً؛ المحتوى العريض يتمرّر
   داخل حاويته وحدها.
2. **بتر الحقول:** خانة تعرض «50» بدل «5000» أو اسماً مبتوراً. هذا **لا يسبّب
   تمدّداً**، فيمرّ صامتاً لولا فحصه صراحةً — وهو الأخطر لأنه يخفي عن المستخدم
   ما أدخله.

الشبكات ذات الأعمدة الثابتة (بنود المصروفات، صفوف الديون) تُعاد تشكيلها تحت
520px عبر `@media` في وسم `<style>`: التسمية على سطر كامل والأرقام تحتها.

**تحفّظ واحد على البيانات المرجعية:** الوثيقة تعطي إجمالي تكلفة الأهداف (24,400)
دون توزيعها على الأشهر الستين. التوزيع في ملف الاختبار اجتهاد يحافظ على الإجمالي
وعلى أول شهر عجز (السنة 1 · مارس). لذلك القيمتان المرتبطتان بالتوزيع تحديداً —
أقصى عجز تراكمي والرصيد الختامي — تختلفان عن رقمي الوثيقة (17,105 و−15,390)،
وتُقارَنان بما ينتجه هذا التوزيع (15,865 و−14,640). بقية القيم تطابق الوثيقة
حرفياً. لو ظهر التوزيع الأصلي يوماً، حدّث `baseCase()` وحدها.

## قواعد ثابتة لا تُكسر

- **RTL:** `dir="rtl"` على الجذر. استخدم `marginInlineStart` و`borderInlineStart`
  لا `marginLeft`/`borderLeft`.
- **الأرقام:** `direction:"ltr"` و`fontFamily:T.mono` على كل خانة رقمية، وإلا
  انقلب ترتيب الأرقام بصرياً. **هذه ليست قاعدة تجميلية.** خانة فيها عدّة مقاطع
  رقمية مفصولة بمحايدات — مثل `65.7% / 16.8% / 17.5%` — تنقلب بصرياً بلا `ltr`
  فتُقرأ `17.5% / 16.8% / 65.7%`، أي يرى الكوتش الاحتياجات ادخاراً والعكس. الأسوأ
  أنّ `textContent` يظلّ صحيحاً بالترتيب المنطقي، فلا يكشفه أي فحص نصّي؛ لذلك
  يفحص `npm run verify` الاتجاه المحسوب نفسه.
  ملاحظة مقابلة: `whiteSpace:"nowrap"` **ليس** جزءاً من هذه القاعدة — إعادته
  تمدّ القيم الطويلة خارج شاشة الجوال، والالتفاف لا يكسر رقماً أصلاً لعدم وجود
  فراغ داخل `53,760`.
- **العملة:** `money(n, cur)` — الريال العماني والدينار الكويتي والبحريني بثلاث
  خانات عشرية، والباقي باثنتين.
- **حقول الأرقام:** `NumberField` يحتفظ بنص داخلي أثناء التركيز حتى لا يُفسد
  الكتابة (`"12."` تكسر التحويل المباشر). لا تبسّطه إلى `value={n}`.
- **لا نموذج `<form>`** — معالجات `onClick` فقط.
- **`exportHtml()` لا يُحذف** — هو المسار الاحتياطي الوحيد للطباعة، ويبني مستنداً
  مستقلاً بتنسيقه الخاص.
- **`recharts` تُستورد كسولاً فقط** — استيرادها مباشرة أعلى `khutta-maliya.jsx`
  يعيد 103ك مضغوطة إلى أول تحميل ويلغي الفصل كاملاً. ولا تُسمَّ في `manualChunks`
  أيضاً: التسمية تُدخِلها في رسم التحميل المسبق فيُضيف Vite لها `modulepreload`
  في الـ HTML وتُحمَّل عند أول فتح رغم كسل الاستيراد. يحرس الأمرين فحصٌ شبكي في
  `npm run verify`.

## إشعار

بطاقات القرار أداة تصنيفية استرشادية مستلهمة من نصوص المال (كلونتز)، والمحاسبة
الذهنية (ثالر)، والخصم المفرط (لايبسون)، ومقياس اتجاهات المال (يامَوتشي وتمبلر).
ليست أداة تشخيص نفسي معتمدة ولم تُقنَّن على عيّنة خليجية. بقية القواعد استرشادية
وليست توصية استثمارية أو قانونية أو شرعية.

تنسيق البطاقات الورقية الأصلي علامة تخص صباح المقبالية، والسيناريوهات هنا أصلية
لكن المنطق مستوحى منها.
